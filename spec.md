# aiZee — Specification

> **aiZee: The policy layer for AI coding.**

## Problem

AI coding assistants (Cursor, Claude, Copilot, Windsurf, Cline, Aider, Devin) hallucinate APIs, forget conventions, ignore security, and silently ship technical debt. There is no centralized governance layer between the AI and the codebase.

## Solution

aiZee is a sovereign, version-controlled operating system that sits between you and every AI coding assistant. It enforces engineering standards, security policies, and architectural discipline on every line of generated code by forcing the AI to read from a centralized source of truth *before* writing a single line.

## Core Principles

1. **Ground-Truth First** — Never write code without reading live docs (Context7 MCP) and codebase graph (graphify) first.
2. **Zero-Defect Delivery** — ruff + mypy strict + pytest + eval/harness must be green before declaring done.
3. **Policy-Governed Actions** — Every action passes through a 5-gate pipeline: Probity → Guardian → Policy → Budget → Audit.
4. **Version-Locked Tech Stack** — Always read lockfiles before loading tech-stack references. Never assume framework versions.
5. **Persona Composition** — Auto-detect the right persona + skills per task. No one-size-fits-all.
6. **Token Efficiency** — Local persona detection (zero LLM tokens). Only relevant skill names returned.
7. **Dogfooding** — aiZee must follow its own rules. This spec exists because the OS enforces specs on projects.

## Architecture

```
aizee/                         # Sovereign root (discovered via AIZEE_ROOT)
├── aizee_cli.py               # CLI entry point (aizee command)
├── config.py                  # Root discovery + version
├── runtime/                   # Kernel: policy, budget, audit, 88 modules
│   ├── kernel.py              # Facade delegating to managers
│   ├── managers/              # PolicyManager, WorkflowManager, AgentManager, ChatManager
│   ├── uninstaller.py         # Interactive uninstaller with backup
│   └── ...                    # 88 governance modules
├── aizee_mcp/                 # MCP server (35 tools, 3 resources)
│   ├── aizee_server.py        # FastMCP server
│   └── tools/                 # Tool modules by responsibility
├── memory/                    # SQLite + FTS5 + vector memory
├── eval/                      # Agent benchmark & eval harness
├── skills/                    # 66 persona + lord skill files
├── workflows/                 # 30 trigger-based execution protocols
├── rules/                     # Compressed behavioral rules
├── tech-stack/                # Version-locked stack references
├── dashboard/                 # Web dashboard (Python stdlib HTTP)
└── scripts/                   # Installers, validators, MCP wrappers
```

## CLI

```
aizee status          # OS health + counts
aizee doctor          # Full diagnostic
aizee persona detect  # Detect personas for a task
aizee check <action>  # Policy + budget gate
aizee test [--full]   # Two-tier testing
aizee uninstall       # Interactive uninstall with backup
```

## Quality Gates

| Gate | Command | Requirement |
|------|---------|-------------|
| Lint | `ruff check .` | 0 warnings |
| Types | `mypy` | 0 errors (strict) |
| Tests (fast) | `aizee test` | ~12s, targeted |
| Tests (full) | `aizee test --full` | 80%+ coverage |
| E2E | `python eval/harness.py` | all_pass: true |

## Non-Goals

- aiZee is NOT an AI model or LLM. It governs AI assistants, it does not replace them.
- aiZee is NOT a code generator. It enforces standards on code generated by other tools.
- aiZee is NOT a CI/CD platform. It integrates with existing CI/CD via quality gates.
