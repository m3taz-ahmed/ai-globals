[TECH] Go 1.23
[OBJ] Statically typed compiled language with goroutines, channels, generics, range-over-func iterators, and a minimal standard library focused on concurrency and tooling.
[RULES]
1. [REQ] Use generics with type parameters (`func Foo[T any](v T)`) for reusable algorithms; constrain types with interfaces or `comparable` where appropriate.
2. [REQ] Use range-over-func iterators (Go 1.23): `func(yield func(K, V) bool)` for custom iteration; use `iter.Seq[V]` and `iter.Seq2[K, V]` types from the `iter` package.
3. [REQ] Use `context.Context` as the first parameter in all functions that perform I/O or may be cancelled; propagate context through call chains, never store it in structs.
4. [REQ] Use `context.WithTimeout` and `context.WithDeadline` for all network/DB calls; never use `context.Background()` in request handlers except for top-level initialization.
5. [REQ] Launch goroutines with clear lifecycle management; use `sync.WaitGroup`, channels, or `context` for cancellation; never launch fire-and-forget goroutines.
6. [REQ] Use channels for ownership transfer and synchronization; use `sync.Mutex`/`sync.RWMutex` for protecting shared state; prefer `sync.Map` only for high-read/low-write concurrent maps.
7. [REQ] Use `errors.Is` and `errors.As` for error inspection; wrap errors with `fmt.Errorf("operation: %w", err)` to preserve context; define sentinel errors with `errors.New`.
8. [REQ] Use `go mod tidy` and `go mod verify` before commits; pin dependencies in `go.mod`; run `govulncheck` in CI for vulnerability scanning.
9. [REQ] Write table-driven tests using `testing.T` and `t.Run` for subtests; use `t.Parallel()` for independent tests; use `testing.F` for fuzz testing.
10. [REQ] Use `pprof` for profiling: import `_ "net/http/pprof"` and use `go tool pprof http://localhost:6060/debug/pprof/profile` for CPU profiles.
11. [REQ] Use `go vet`, `staticcheck`, and `golangci-lint` in CI; run `gofmt`/`goimports` on every file to enforce formatting standards.
12. [REQ] Use `cgo` only for binding to C libraries; isolate cgo calls behind a pure-Go interface; set `CGO_ENABLED=0` for static binaries in containers.
13. [REQ] Use `any` (alias for `interface{}`) in Go 1.23; prefer concrete types or type parameters over `any` for type safety.
14. [PROHIBIT] Never panic across goroutine boundaries; recover panics in goroutine launchers or use structured error channels to prevent process crashes.
15. [PROHIBIT] Never use `time.Sleep` for synchronization in production code; use channels, `sync.Cond`, or `context.WithTimeout` for deterministic waiting.
[COMPAT]
- v1.23: Generics (since 1.18), range-over-func iterators, `iter` package, `slices` and `maps` packages in stdlib
- v1.23: Go modules (Go 1.23 toolchain directive), `go test -fuzz`, `go vet` with improved analyzers
- v1.23: `CGO_ENABLED`, cross-compilation, `GODEBUG` flags, `go tool pprof`, `go tool trace`
